# 공개 범위

## 승인된 공개 범위

사용자 승인은 프로젝트명·일반 기능 소개와 별도로 작성한 독립 구현·README·테스트·기술 설명·검증 방법·독립 예제의 테스트 결과에 한정됩니다. 원본·팀 자료나 실제 성능 측정 자료의 공개 권리는 승인된 것으로 취급하지 않습니다.

## 포함한 자료

- 사용자가 제공한 프로젝트 명칭·기능 소개.
- 원본 코드·설정·데이터·테스트를 복사하지 않고 새로 작성한 최소 예제.
- 예제의 설계 도식·실행 방법·합성 테스트·로컬 결과.
- 일반 검증 절차와 공개 폴더의 정적 점검 도구.

예제는 원본 제품과 동일한 구현이 아닙니다. 합성 입력과 단순 계약으로 기술적 선택을 설명합니다. 개발에는 Coding Agent를 활용했고 원본의 사람·팀·Agent 기여를 바꾸지 않습니다.

## 제외한 자료

원본 소스·테스트·골든셋, 실제 모델 비교·시연 DB·CI 집계, 팀 원본 도식·문서, 제조 데이터·이미지, 운영 주소·경로·설정, 자격 파일, 개인정보, 수상 증빙은 포함하지 않습니다. 권리와 실제 개인 기여는 저장소 밖에서 확인합니다.

예제의 실행 성공은 원본 프로젝트 성능·실사용·장기 운영을 증명하지 않습니다. 기존 Git 이력·작성자는 변경하지 않았습니다.

## 정적 점검

허용 목록은 공개 대상 파일17개를 명시합니다. 신규 자료·PDF를 넣을 때 내용·권리를 검토한 뒤 목록·파일 형식 정책을 함께 갱신합니다. 미허용 파일, 심볼릭 링크·junction, 로컬 링크의 폴더 이탈, 의심 정보 패턴을 검사합니다.

통과는 모든 비밀의 부재나 공개 권리 검토를 보증하지 않습니다. `.gitignore`도 보안 경계가 아니므로 실제 파일을 검사합니다. Java 컴파일은 임시 폴더에서 하고 Python 캐시는 `-B`로 만들지 않습니다.
